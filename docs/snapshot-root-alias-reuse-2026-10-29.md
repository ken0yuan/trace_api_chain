# 同一快照的入口别名重复校验修复

旧优化已经减少遍历内部的重复对象访问，但入口循环仍然先生成递归签名，再判断能否复用。实际原生回调同时传入 `callable=dict.get` 和 `receiver=字典`：从 callable 的 receiver 边已经触及字典，随后独立 receiver 根又校验一次。缓存组件校验还可能令同一字典出现第三次递归校验。这是旧修复覆盖不全，不是新的业务分支。

本修复仅用于完整观察候选，不包含两层边界或数据容器省略。它协调同一快照中的入口：保留 callable、receiver 及所有入口别名边，由明确的 receiver 入口执行一次完整校验。精确内建函数的暂存边不能作为完整子树缓存；只有当前快照已观察到的 token 才能用于入口复用。入口协调仅保存身份与 token，不延长业务对象生命周期。下一次快照仍验证变化，测试覆盖新增深层引用、循环、多入口和缓存条目淘汰。

## 验证与适用范围

- 直接因果复现：旧实现对同一 receiver 的递归校验分别为 2、2、3 次（首次、未变化、新分支）；修复后三者均为 1 次，gaps 为空。
- 最终 v3 候选：trace 249 项回归通过；API 121 项通过、9 项跳过。六项可选联合回归按用户要求不运行。中间 v2 未通过组件复用回归，不作为可发布版本。
- 同一组真实 torch/torch_npu/TBE 注册表对象及新增模块，交换新旧执行顺序：7.5014→6.2217 秒、7.6055→6.0835 秒。开始事件之后的完整对象记录逐字节相同，SHA256 为 `fbc6a671b6ed9cc7cfda73a5722875a80b2dd7666198605c18d1c461dd4b7c63`，无缺口。此为对象快照 CPU 对照，不是完整 NPU 用例的加速结论。
