# 减少重复劳动，保留完整调用链

此候选基于完整采集分支，不含两层限制或基础容器摘要。目标是减少相同工作的重复执行，不改变实体、引用、分支、API 别名或来源支持。

## 改动

1. 基础标量序列的增量快照复用已验证的不可变邻接集合。追加时直接生成下一份不可变集合，避免先复制为可变集合、再复制回不可变集合。全量身份检查仍执行；替换、删除和混合成员按原规则观察。
2. 符号解析原来已按库批量执行；新增的是跨测试的**只读、按内容校验的符号索引**。索引键包含完整 ELF SHA256、解析器源码 SHA256、符号工具版本。缓存原始符号帧，不缓存源码快照；每个测试仍读取并校验当前源码内容。新地址、换库、换解析器、换工具版本、损坏或冲突均回到私有解析。未成功解析的工具错误不冒充缓存成功。
3. 多条路径支持同一份来源证据时，每种证据文本只解码、编码一次，再复用相同 JSON 文本。路径支持集合及顺序保持不变，输出文本与原实现逐字节相同。
4. 将此前已验证的源码索引优化与当前离线整理链衔接；任务适配器可通过 `CALLCHAIN_READONLY_SYMBOL_INDEX` 指定只读索引。旧冻结交接仍使用原始读器，不向旧读器塞入新参数。

索引生产者和消费者分离。生产者从已完成的私有 `symbol-cache` 发布到**新目录**，最后原子发布 manifest；已经发布的目录不再更新。消费者从索引读取，每例的缺失地址只写自己的工作区，不向共享目录追加内容。多份私有缓存可合并相同库的不同地址；同一地址的符号帧有冲突则拒绝发布。此索引仅复用固定二进制的地址解释，不共享或合并测试图。

## 使用

```sh
python -c 'from trace_api_chain.cli import main; raise SystemExit(main())' symbol-index /completed/private/symbol-cache --out /new/readonly-index
python -c 'from trace_api_chain.cli import main; raise SystemExit(main())' prepare /capture --out /private/refresh-plan.json --symbol-index /new/readonly-index
```

任务适配器通过 `CALLCHAIN_READONLY_SYMBOL_INDEX` 指定索引路径。
