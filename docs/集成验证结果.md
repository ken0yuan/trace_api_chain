## 2026-10-25 历史基线

验证日期：2026-10-25。Linux/WSL Ubuntu-22.04、CPython 3.11、真实插桩 PyTorch CUDA。

pytest11 安装包验证：40 项测试通过，包括采集与重放隔离、后端私有成员、实例和别名合并、API 分支隔离、SQL 回滚、别名撤销和源码变化失效。C++ 声明读取器用真实编译的同名重载函数验证。

真实采集：`examples/test_runtime.py::test_add_and_compile_exclusion` 测试通过，采集阶段耗时 17.25 秒。回执标记 replay_performed、database_written、html_generated 均为 false。实际仅记录两次 torch.add；torch.compile 别名和其返回包装器有显式排除记录。该时间包含 pytest 启动等成本，不代表裸采集开销。

共享数据库现有 2 份采集贡献、2171 个实体、18536 个上下文路径。每份证据重复重放均返回 unchanged，路径总数保持 18536。SQLite integrity_check 为 ok，foreign_key_check 为空。

独立从 SQL 导出 torch.Tensor.fill_：1699 个路径节点、720 个实体。浏览器已确认 C03 能展开 DWARF 定位的 THPVariable_fill_ 定义，文件为 pytorch/torch/csrc/autograd/generated/python_variable_methods.cpp，第 7064 行。torch.add 也可独立从同一库查询，共 1654 个路径节点。

库中有 1,881 个已映射实体、290 个未解析函数实体，以及 187 条待确定对象归属记录。未解析并不等于没有采集；它们没有被按名字强行合并。该 CUDA 样本中的对象主要缺少可证明的 Python 类定义锚点，fill_ 页面因此显示 0 个已归一化源码对象。后端 Python 类及私有对象归并由独立 pytest 用例验证。

TorchNPU 使用同一命名空间/源码根和 SQL 流程；本机没有完成真实 TorchNPU/NPU 硬件验证。数据库覆盖已导入的运行证据，不能把尚未执行的整个 PyTorch/TorchNPU 库宣称为已完整采集。当前 pytest 入口一次接受一个明确 nodeid，多份记录由离线命令统一导入。

完整数值见项目内 data/sql-validation.json 与 idempotence-validation.json。源码和安装包不依赖这些验证目录；HTML 生成只需要 SQL 数据库。
