# 超时、TBE 环境与写库重复扫描修复（2026-10-29）

本文记录本次真实诊断。修复候选为 trace-api-chain 0.3.4、api-test-relations 0.1.11。源码版本、部署时间和最终原始用例验收以服务器维护记录为准；候选回归通过不等于正式全量测试全部通过。

## 为什么会出现很多超时

“超时”只表示采集子进程超过 1800 秒，并不能说明 NPU 卡冲突、测试没进入、函数调用返回失配或断言失败。现场栈与失败证据揭示了不同阶段的问题：

1. Transformer 等用例的数据构造、深拷贝会访问很大的对象图。每次重新观察时，插件需要确认对象及引用是否变化；共享父类的方法描述原来会在同一次签名计算里重复编码。新实现只在该次计算中复用父类描述，下次观察仍重新检查类字典和函数源码位置，包括原地替换 `__code__`。
2. 原生函数入口身份解析每次都重新初始化 ctypes 接口。现在只复用接口配置，每个实际函数的地址、库和文件状态仍重新解析，不把不同函数混为一个。
3. Python 审计钩子对大量无关审计通知反复进入 Python，然后立即返回。关系插件现用 C 入口识别原有七种生命周期通知，仍调用原来相同的 Python 处理器；API 观察、分支、线程与子进程保护不缩减。
4. 每次返回原来都遍历所有活跃调用的引用视图，寻找当前调用拥有的条目。深层 CANN 导入使它变成大量重复扫描。现在按调用帧建立所有权索引，只回收确实返回的调用自己的条目，保留其他调用的全部视图。
5. 在隔离复测中，有的测试已经在终端输出通过、原始事件也写了最终 `end`，却仍超时。现场栈停在采集结束的 `windows.json` 缩进序列化：原来每次暂停与恢复都保存一份窗口回执。路径模式已经按同一源码上下文累计原生路径，因此这些窗口回执可以按相同上下文累计。新实现保留代表窗口、全部事件总数、激活次数和失败标记；所有真实进入、退出以及栈一致性检查仍执行。JSON 只是改成紧凑编码，各字段值不因编码改变。

这些修复没有减少 10,362 项 API 目录，没有降低事件、路径、引用预算，没有缩短测试，也没有根据“相关性”删除对象。真正新的对象、引用和分支仍需要处理。未验证的子进程片段继续保留，不声明为完整跨进程图。

## TBE 导入为什么失败

TBE 是当前 CANN 安装的一部分，不是 torch-npu wheel 自带的普通依赖。正式驱动覆盖 `PYTHONPATH` 后，官方 CANN Python 路径丢失；隔离 venv 还缺少 CANN 声明的 `decorator`、`attrs`。因此机器上有 TBE，不代表测试进程能导入。

在现有 venv 的 site-packages 中增加 `callchain_cann_runtime.pth`，只加入当前安装的两个官方组件路径：

```
/usr/local/Ascend/cann-9.2.0/python/site-packages
/usr/local/Ascend/cann-9.2.0/opp/built-in/op_impl/ai_core/tbe
```

补入 decorator 5.3.1、attrs 26.1.0。网络安装不可用时，从系统已有安装重建离线 wheel：逐个校验 RECORD 哈希，确认 `Root-Is-Purelib` 与 `py3-none-any`，没有混入另一 Python 版本的二进制扩展。使用 `--no-index --no-deps --no-compile` 安装，仅补这两个包。PyTorch、torch-npu 和编译选项不变。

在正式驱动相同环境变量、`PYTHONSAFEPATH=1` 下验证 `tbe`、`te` 和平台模块的实际导入路径。不能只凭 import 成功声称 LSTM 用例已经通过：三个原始 LSTMCell 用例必须分别检查测试回执及完整调用链。

## 写库慢在哪里

采集、离线整理仍可并行；只有最终写两个 SQLite 数据库的线程串行。原实现每提交一个用例都对整座调用链数据库执行 `PRAGMA foreign_key_check`，还会全局寻找不再有测试支持的路径。数据库约 39.7GB 后，旧历史反复被扫描，比本次新增写入本身更贵。

修复在唯一写库线程复用一个连接。首次事务先完整校验历史；以后仍开启 SQLite 外键约束，真实写入由 SQLite 逐条和提交时检查。若其他连接提交数据，`PRAGMA data_version` 变化，必须重新完整检查。它不是忽略外键错误：坏历史、新增坏引用和外部错误写入均有拒绝与回滚回归。

首次成功提交执行原有全局无支持路径清理；以后只检查当前输入与被替换槽位可能影响的路径。这仍执行原有“没有任何支持”条件，保留其他用例支持的全部路径；外部写入发生后重新全局检查。NULL 路径主键的旧行为也保留。

`database.py`、离线图重建和交接格式保持不变。新增 `WriterSession` 私有连接适配器复用原提交函数；不会修改其他线程使用的全局连接函数。已有冻结交接文件不需要重新采集或重新整理。

## 大图元数据复用与分阶段恢复

旧元数据缓存超过十万条就全部清空。实际 TBE 隔离采集已出现约二十七万种观察对象，整批清空会丢掉仍可精确验证并复用的描述。新缓存按已有引用观察预算保留元数据（至少十万条），达到容量时只淘汰最久未用条目；每次命中仍校验类型上下文、函数源码等身份条件。这里只增加已证明相同描述的复用空间，不改变引用、路径或 API 的采集上限，也不缓存用户实例本身。结束回执保留命中、未命中和淘汰计数，以便继续核实性能。

恢复可以分两步进行：在 `CAPTURE_PAUSE` 文件存在时，新驱动继续并行整理和串行写库，但不启动正式 NPU 测试。原始问题用例完成隔离验收且卡已空闲后，再移除该采集准入标记恢复八卡。`STOP` 仍是完整停止新增工作的请求，两者含义不同。诊断未完成时不能把仅恢复消费称为八卡采集已恢复。
